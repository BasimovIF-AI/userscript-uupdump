Документ предназначен для AI-ассистентов и разработчиков при сопровождении, тестировании и модификации проекта `userscript-uupdump`.

---

## 1. МИССИЯ, KPI И ГРАНИЦЫ ПРОЕКТА (MISSION & SCOPE)

### Миссия
Обеспечить мгновенную, динамическую фасетную фильтрацию и живой клиентский поиск по таблице найденных сборок на страницах сервиса **UUP dump** (`uupdump.net`) без необходимости перезагрузки страниц или отправки повторных тяжелых запросов к серверу.

### Измеримые KPI
1. **Zero Latency Filtering:** Время реакции интерфейса при переключении любого фильтра или вводе поискового запроса < 15 мс (для списков до 1000 строк).
2. **100% точность классификации:** Корректное выделение семейства ОС (Windows 11, Windows 10, Server, Cloud PC), архитектуры (x64, arm64, x86), ветки (rs_prerelease, rs_flight и др.) и типа сборки (Cumulative, Feature, Insider).
3. **Бесшовный визуал (Semantic UI Native):** Использование встроенных в UUP dump классов Semantic UI для идеальной интеграции без конфликтов тем оформления (Light/Dark).
4. **Чистый DOM:** Корректное скрытие/отображение строк (`display: none` / `table-row`) с сохранением целостности верстки и ссылок.

### Не-цели (Non-Goals)
- Модификация серверных API или обход защит Cloudflare при запросе внешних страниц.
- Парсинг файлов с языковыми пакетами (`selectlang.php`) или конвертеров скриптов (`get.php`). Скрипт работает строго на обзорных страницах со списками сборок (`known.php`, `fetchupd.php`, страницы поиска `?q=...`).

## 3. АРХИТЕКТУРНЫЕ ПРАВИЛА И ИНВАРИАНТЫ

1. **Изолированный движок парсинга:**
   - Вся логика извлечения атрибутов (`parseRow`, `normalizeArch`, `detectOS`, `detectVersion`, `detectBranch`, `detectType`) чистая и детерминированная.
   - Любые изменения в алгоритмах распознавания обязаны сопровождаться соответствующими тестовыми случаями в [`test_filter_engine.js`](file:///e:/Ильгиз/Documents/VibeCoding/TM_Scripts/userscript-uupdump/test_filter_engine.js).
2. **Динамический сбор фасетов:**
   - Список кнопок-чипов формируется динамически на основе **фактически загруженных** в DOM строк. Если на текущей странице нет сборок arm64 или нет Windows Server — соответствующие чипы не создаются, не засоряя экран.
3. **Логика фильтрации:**
   - Между группами категорий (`arch`, `os`, `version`, `branch`, `updateType`) применяется логическое **И (AND)**.
   - Внутри одной категории применяется логическое **ИЛИ (OR)** (пользователь может выбрать `x64` и `arm64` одновременно).
   - Поисковая строка токенизируется по пробелам, каждое слово проверяется на вхождение без учета регистра.
4. **Debounce для поиска:**
   - Ввод в текстовое поле дебаунсится на 100 мс для предотвращения лишних перерисовок DOM при быстром наборе текста.

## 4. ПОДВОДНЫЕ КАМНИ И НЕТРИВИАЛЬНЫЕ РЕШЕНИЯ

1. **Разнообразие форматов названий в UUP dump:**
   - Некоторые сборки пишутся как `Windows 11, version 26H2 (26300.9807) amd64`, другие — как `Cumulative Update for Windows CPC OS (10.0.26300.9711) (26300.9711) amd64`, третьи — как `Windows Server Insider Preview 29683.1000 (rs_flight) amd64`.
   - Регулярные выражения спроектированы так, чтобы извлекать номер ветки из скобок только если это ветка разработки (`rs_prerelease`, `rs_flight` и т.д.), не путая её со вторыми скобками номера сборки.
2. **Поддержка MutationObserver:**
   - UUP dump может обновлять содержимое контейнеров через пагинацию или частичные динамические вставки. `MutationObserver` с дебаунсом 300 мс следит за наличием панели и корректно переинициализирует фильтры, если таблица была пересоздана.
