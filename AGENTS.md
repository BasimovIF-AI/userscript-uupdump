# AGENTS.md — AI-нативный операционный мануал

Документ предназначен для AI-ассистентов и разработчиков при сопровождении, тестировании и модификации проекта `userscript-uupdump`.

---

## 1. МИССИЯ, KPI И ГРАНИЦЫ ПРОЕКТА (MISSION & SCOPE)

### Миссия
Обеспечить мгновенную, динамическую фасетную фильтрацию и живой клиентский поиск по таблице найденных сборок на страницах сервиса **UUP dump** (`uupdump.net`) без необходимости перезагрузки страниц или отправки повторных тяжелых запросов к серверу.

### Измеримые KPI
1. **Zero Latency Filtering:** Время реакции интерфейса при переключении любого фильтра или вводе поискового запроса < 15 мс (для списков до 1000 строк).
2. **100% точность классификации:** Корректное выделение семейства ОС (Windows 11, Windows 10, Server, Cloud PC), архитектуры (x64, arm64, x86), ветки (rs_prerelease, rs_flight и др.), номеров сборок (Build Number / Revision) и типа сборки (включая обособление .NET Framework Update, Cumulative, Feature, Preview, Insider).
3. **Бесшовный визуал (Semantic UI Native):** Использование встроенных в UUP dump классов Semantic UI для идеальной интеграции без конфликтов тем оформления (Light/Dark).
4. **Чистый DOM:** Корректное скрытие/отображение строк (`display: none` / `table-row`) с сохранением целостности верстки и ссылок. Отсутствие пустых групп фильтров при отсутствии данных.

### Не-цели (Non-Goals)
- Модификация серверных API или обход защит Cloudflare при запросе внешних страниц.
- Парсинг файлов с языковыми пакетами (`selectlang.php`) или конвертеров скриптов (`get.php`). Скрипт работает строго на обзорных страницах со списками сборок (`known.php`, `fetchupd.php`, страницы поиска `?q=...`).

## 3. АРХИТЕКТУРНЫЕ ПРАВИЛА И ИНВАРИАНТЫ

1. **Изолированный движок парсинга:**
   - Вся логика извлечения атрибутов (`parseRow`, `normalizeArch`, `detectOS`, `detectVersion`, `detectBranch`, `detectType`, `detectBuildNumber`) чистая и детерминированная.
   - Любые изменения в алгоритмах распознавания обязаны сопровождаться соответствующими тестовыми случаями в [`test_filter_engine.js`](file:///e:/Ильгиз/Documents/VibeCoding/TM_Scripts/userscript-uupdump/test_filter_engine.js).
2. **Динамический сбор фасетов:**
   - Список кнопок-чипов формируется динамически на основе **фактически загруженных** в DOM строк. Если данных по категории нет (`statsMap.size === 0`) — соответствующая строка фильтров не рендерится вообще.
3. **Логика фильтрации:**
   - Между группами категорий (`arch`, `os`, `version`, `branch`, `updateType`, `buildNumber`) применяется логическое **И (AND)**.
   - Внутри одной категории применяется логическое **ИЛИ (OR)** (пользователь может выбрать `x64` и `arm64` одновременно, либо несколько ревизий сборок).
   - Поисковая строка токенизируется по пробелам, каждое слово проверяется на вхождение без учета регистра.
4. **Сортировка фасета сборок:**
   - Чипы с номерами сборок (`buildNumber`) сортируются численно по убыванию ревизий (более свежие сборки первыми). При большом количестве сборок (> 8) активируется компактный контейнер со скроллом.

## 4. ПОДВОДНЫЕ КАМНИ И НЕТРИВИАЛЬНЫЕ РЕШЕНИЯ

1. **Разнообразие форматов названий и .NET Framework:**
   - Некоторые сборки не имеют явной подстроки `version 26H2` в заголовке (например, `.NET Framework Security Update for Windows 11 - KB5127694 (26300.10008)` или `Cumulative Update for Windows CPC OS (10.0.26300.9711)`). Движок использует интеллектуальный вывод релиза по номеру сборки (`26300.*` $\rightarrow$ `26H2`).
   - Пакеты `.NET Framework` получают приоритетную классификацию `.NET Framework Update`, предотвращая их смешивание со стандартными установщиками ОС.
2. **Поддержка MutationObserver:**
   - UUP dump может обновлять содержимое контейнеров через пагинацию или частичные динамические вставки. `MutationObserver` с дебаунсом 300 мс следит за наличием панели и корректно переинициализирует фильтры, если таблица была пересоздана.
