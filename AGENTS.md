Документ предназначен для AI-ассистентов и разработчиков при сопровождении, тестировании и модификации проекта `userscript-uupdump`.

---

## 1. МИССИЯ, KPI И ГРАНИЦЫ ПРОЕКТА (MISSION & SCOPE)

### Миссия
Обеспечить мгновенную, динамическую фасетную фильтрацию и живой клиентский поиск по таблице найденных сборок на страницах сервиса **UUP dump** (`uupdump.net`) без необходимости перезагрузки страниц или отправки повторных тяжелых запросов к серверу.

### Измеримые KPI
1. **Zero Latency Filtering:** Время реакции интерфейса при переключении любого фильтра или вводе поискового запроса < 15 мс (для списков до 1000 строк).
2. **100% точность классификации:** Корректное выделение категории пакета («Полные сборки» vs «Обновления»), семейства ОС (Windows 11, Windows 10, Server, Cloud PC), архитектуры (x64, arm64, x86), ветки (rs_prerelease, rs_flight и др.), номеров сборок (Build Number / Revision) и типа сборки (включая обособление .NET Framework Update, Cumulative, Feature, Preview, Insider).
3. **Бесшовный визуал (Semantic UI Native):** Использование встроенных в UUP dump классов Semantic UI для идеальной интеграции без конфликтов тем оформления (Light/Dark).
4. **Чистый DOM и реактивность:** Корректное скрытие/отображение строк (`display: none` / `table-row`). Динамический пересчет счетчиков фасетов, блокировка (`disabled`) пустых чипов и скрытие (`hidden`) недоступных опций из выпадающего списка сборок.

### Не-цели (Non-Goals)
- Модификация серверных API или обход защит Cloudflare при запросе внешних страниц.
- Парсинг файлов с языковыми пакетами (`selectlang.php`) или конвертеров скриптов (`get.php`). Скрипт работает строго на обзорных страницах со списками сборок (`known.php`, `fetchupd.php`, страницы поиска `?q=...`).

## 3. АРХИТЕКТУРНЫЕ ПРАВИЛА И ИНВАРИАНТЫ

1. **Изолированный движок парсинга:**
   - Вся логика извлечения атрибутов (`parseRow`, `detectPackageCategory`, `normalizeArch`, `detectOS`, `detectVersion`, `detectBranch`, `detectType`, `detectBuildNumber`) чистая и детерминированная.
   - Любые изменения в алгоритмах распознавания обязаны сопровождаться соответствующими тестовыми случаями в [`test_filter_engine.js`](file:///e:/Ильгиз/Documents/VibeCoding/TM_Scripts/userscript-uupdump/test_filter_engine.js).
2. **Приоритет группы «Категория»:**
   - Первой строкой панели фильтров всегда располагается группа «Категория» («Полные сборки» / «Обновления»).
3. **Динамический сбор фасетов и контекстный пересчет:**
   - Список кнопок-чипов и выпадающий список формируются динамически на основе **фактически загруженных** строк.
   - При переключении любого фильтра счетчики оставшихся категорий пересчитываются (`computeDynamicFacetCounts`), чипы с 0 элементов становятся `disabled`, а опции выпадающего списка с 0 элементов полностью скрываются (`opt.hidden = true; opt.style.display = 'none'`).
4. **Логика фильтрации:**
   - Между группами категорий (`packageCategory`, `arch`, `os`, `version`, `branch`, `updateType`, `buildNumber`) применяется логическое **И (AND)**.
   - Внутри одной категории чипов применяется логическое **ИЛИ (OR)**.
   - Выпадающий список «Сборка (Build)» выбирает целевую ревизию либо «Все сборки».

## 4. ПОДВОДНЫЕ КАМНИ И НЕТРИВИАЛЬНЫЕ РЕШЕНИЯ

1. **Сброс выбора сборки при конфликте:**
   - Если пользователь выбрал сборку, а затем включил фильтр, с которым эта сборка не имеет ни одного совпадения (0 элементов), выбор сборки автоматически сбрасывается в положение «Все сборки», чтобы исключить отображение пустого экрана.
2. **Поддержка MutationObserver:**
   - UUP dump может обновлять содержимое контейнеров через пагинацию или частичные динамические вставки. `MutationObserver` с дебаунсом 300 мс следит за наличием панели и корректно переинициализирует фильтры, если таблица была пересоздана.
